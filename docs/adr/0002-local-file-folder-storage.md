# ADR-0002: 采用本地文件 + 文件夹作为唯一存储

**状态**: superseded（2026-08-21 由 [ADR-0004](0004-sqlite-sea-orm-storage.md) 取代：存储改为数据根目录内的 SQLite + sea-orm；本文件保留作历史记录）
~~accepted（2026-08-20 v2：更新为团队/项目模型与 JSONC）~~

产品核心卖点是"纯离线 + 数据是文件"。数据根目录即数据源，按**模块**划分（当前为接口管理模块 `api-mgmt/`，未来新模块并列目录）；模块内团队/项目/分组为目录、接口为单个含 `version`/`id`/`name` 字段的 JSONC 文件；`workspace.json`、`team.json`、`project.json`、`group.json` 与 `environments/*.json` 保存元数据（环境与全局变量/全局参数挂在项目上）。不做数据库、不做服务端同步。

之所以坚持"文件即真相"：目录可整体复制/归档/进 git，天然满足离线、可移植、团队 review 需求；避免引入数据库后"文件是为了给人看，DB 是真相"的双轨不一致。

**Considered Options**:
- SQLite 持久化 + 导出文件：性能好、查询能力强，但引入存储真相二元性，且"打开一个文件夹就是数据根目录"的体验被破坏。
- JSON 单文件整体存储整个数据根目录：实现简单，但大团队/项目会读写放大、diff 不友好、并发写冲突概率高。

**Consequences**:
- 需要自行实现目录树扫描、原子写、`notify` 外部变更监听、并发打开冲突处理（锁文件 + 时间戳提示）。
- 团队/项目/分组/接口的目录名与文件名使用英文（小写字母、数字、连字符），兼容不同操作系统；中文显示名存各文件元数据 `name` 字段。接口名独立于文件名：重命名不移动磁盘文件，避免 git 历史噪音；文件系统仅作为人类可读键与拖拽移动的载体。
- 所有数据文件采用 JSONC（读取宽容注释/尾逗号，程序写入生成标准 JSON）；JSONC 注释丢失问题见 risks。
- 标签栏状态（打开的项目 + 当前激活标签）持久化在 `workspace.json`，程序退出还原、下次启动恢复。
- 数据版本由各文件内 `version` 字段承载，升级走迁移钩子。
