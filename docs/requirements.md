# Apidock 需求文档

> 版本：1.0（初稿）
> 状态：待评审
> 日期：2026-08-20

## 1. 项目定位

Apidock 是一个**纯离线**的 API 管理工具。对标 Apifox / Apipost / Postman 的核心能力，但存储层完全采用**本地文件 + 文件夹**结构，无数据库、无服务端、无账号、无遥测。所有 API 数据以 JSON 文件形式组织成目录树，`git` 或直接复制目录即可协作与备份。支持对已保存的请求做真实的 HTTP 请求测试，并支持 OpenAPI 格式的导入与导出。

## 2. 目标与非目标

### 2.1 目标
- 管理 API：以树形结构（数据根目录 → 团队 → 项目 → 分组 → 接口）增删改查 API 定义。
- 请求测试：对任意请求执行真实 HTTP 调用，查看响应详情。
- 纯离线：安装后不依赖任何外部网络，支持内网环境（含需要自定义 CA 证书的场景）。
- 开放存储：所有数据为人类可读的 JSON 文件，目录结构清晰，可被 git 管理、被脚本处理。
- 互操作：支持导入/导出 OpenAPI（3.0 / 3.1），并支持导入 Postman Collection。

### 2.2 非目标（明确不做）
- 不做多用户协作服务端、不做云端同步；不提供用户/成员/权限体系（离线单机无账号）。
- 不做 Mock 服务、不做服务器端网关，不代理他人的流量。
- 一期不做脚本沙箱（如 Postman Pre-request/Tests 脚本），变量替换与断言先以内置规则实现。
- 一期不做「测试用例」管理（接口仅含定义与调试）。
- 不追求移动端。

## 3. 用户与使用场景

- **个人开发/前端联调**：在没有 Postman 的离线环境中，把接口保存在本地目录，随项目走。
- **后端开发**：本地文件即仓库，接口定义随代码提交 git，review 可读。
- **内网环境**：无外网、无公网账号权限，需要管理内网服务的 API 并测试，可能使用自签证书或内网 CA。

## 4. 功能需求

优先级说明：**P0** = 首个可用版本（MVP）必须包含；**P1** = 紧随其后的增强版；**P2** = 远期可选。

### 4.1 数据根目录、模块、团队/项目与文件存储（P0）

1. 首次启动需选择/新建一个本地目录作为**数据根目录**（提供默认位置）；之后启动直接进入主窗口。
2. 数据根目录下放置 `workspace.json`：格式版本号、标签栏状态（打开的项目、当前激活标签、上次打开的项目）。团队清单可由目录扫描得出。
3. 数据根目录按**模块**划分：当前实现「接口管理」模块（目录 `api-mgmt/`），团队/项目/分组/接口均归属于该模块下；后续新增模块（如文档、代码片段）在根目录并列新增目录。
4. 团队 = 模块下的一层目录（元数据 `team.json`）；项目 = 团队目录下的目录（元数据 `project.json`）；分组 = 项目内可嵌套子目录（各含 `group.json`）；接口 = 叶子 JSONC 文件。四者构成本地目录树。
5. 团队/项目的增删改查；树形导航：展开/折叠、新建分组/接口、重命名、复制、删除、拖拽移动。
6. 删除项目/接口文件时允许连带删除磁盘文件；重命名/移动同步到磁盘，保持目录与磁盘一致。
7. 所有数据文件（`workspace.json` / `team.json` / `project.json` / `group.json` / 环境 / 接口）采用 **JSONC**：允许 `//`、`/* */` 注释与尾逗号；程序读取时宽容解析，自身写入时生成标准 JSON。
8. 文件写入采用**原子写**（先写临时文件再 rename），避免应用崩溃或断电损坏文件。
9. 监听外部变更（如 git pull、外部编辑器修改），检测到后自动刷新树与当前打开页。
10. **命名规则**：团队/项目/分组/接口的目录名与文件名使用英文（小写字母、数字、连字符，无空格与其它特殊字符），以兼容不同操作系统；中文等显示名存于各文件元数据 `name` 字段。新建时由显示名自动生成唯一英文键（可手工修改）。

### 4.2 界面布局与标签页（P0）

1. **主窗口**：左侧为团队列表（搜索、新增、删除、修改团队名）；右侧为选中团队内的项目列表（新增、搜索）。点击项目即打开项目标签并进入项目主页，整体布局参考 Apifox。
2. **顶部标签栏**：最左侧为「主窗口」标签，不可关闭；往右依次为已打开的项目标签，鼠标悬停显示关闭按钮（x），点击关闭对应项目。
3. 关闭程序时持久化标签栏状态（打开的项目列表 + 当前激活标签）；下次启动自动恢复主窗口与上次打开的项目。
4. **项目主页（Project Home）**：项目打开后的概览页（项目名称、接口总数、环境状态、快速入口）；无用户/成员/权限/团队设置等入口（离线单机无账号）。
5. **项目页面**：左侧为接口树（多级分组、搜索、展开/折叠）；右侧为接口多标签，每个标签内为接口的视图切换栏：
   - **文档（只读）**：定义的可读展示（方法 + URL、请求参数、请求体、接口说明，以及所属目录等元数据），不可修改。
   - **编辑（定义）**：可修改的定义表单（方法 / URL / 查询参数 / 请求头 / 请求体 / 鉴权 / 断言 / 接口说明）。
   - **调试（发送）**：发送请求并查看响应。
6. 接口树尾部预留不分组的临时接口入口，P0 不实现（Apifox 的「快捷请求」为 P2）。
7. 项目内预留纵向功能区（P1：请求历史、一键运行、项目设置），P0 仅以接口管理树为主入口。

### 4.3 接口定义（P0）

接口文件（JSONC）为一个 JSON 对象，至少包含：

- `id`：稳定标识（UUID）。
- `name`：显示名（默认取文件元数据 name，与英文文件名分离）。
- `method`：HTTP 方法（GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS 及自定义）。
- `url`：目标 URL（可用变量模板，如 `{{host}}/api/login`）。
- `headers`：请求头列表（key/value/是否启用）。
- `query`：查询参数列表（key/value/是否启用），支持 URL 编码选择。
- `body.mode`：`none | json | raw | urlencoded | form-data | file`。
  - `json`：以 JSON 文本保存，提供格式化/校验；编辑区语法高亮。
  - `raw`：任意原始文本，可指定 Content-Type。
  - `urlencoded`：键值列表。
  - `form-data`：键值 + 文件字段列表。
  - `file`：选择一个本地文件作为请求体。
- `auth`：`none | bearer | basic | api-key | digest`（P0 覆盖前四种；OAuth 2.0 归入 P1）。
- `assertions`（P0 提供状态码断言，P1 扩展 JSONPath/头/耗时断言）：列表。
- `variables`：接口级变量（优先级最高）。
- `description`：接口说明（可选，支持 Markdown 渲染）。

接口在 UI 中以两种视图呈现同一个定义：**文档**（只读渲染）与**编辑**（可修改表单）。离线单机无账号，因此不包含创建者/修改者/责任人等用户元数据。

### 4.4 环境与变量（P0）

1. 环境以**项目为单位**，默认内置「正式环境 / 测试环境 / 开发环境」三套，可删除、修改，并支持自定义环境（存于 `项目/environments/*.json`）。
2. 每个环境包含 `host` 与变量列表（`key/value/是否启用`）；环境决定了请求发往哪里（如 `{{host}}`）。
3. 每个项目支持**全局变量**（参与 `{{var}}` 替换）与**全局参数**（向每个请求注入 Header / Cookie / Query / Body）。
4. 支持 `{{key}}` 模板语法；变量替换优先级：**接口级 > 项目全局变量 > 环境变量**。
5. 替换生效范围：URL、查询参数、请求头、请求体（json/raw/form 等）、鉴权字段。
6. 未解析的模板需在发送前给出醒目提示，可配置为阻止发送或放行。
7. （P1）支持从响应中通过 JSONPath 提取值存入环境变量 / 项目全局变量 / 接口变量。

### 4.5 接口测试（P0）

1. 点击「发送」后，Rust 后端发起真实 HTTP 请求，UI 不阻塞（异步执行 + 可取消）。
2. 请求配置项：超时时间（可配置）、重定向策略（跟随/不跟随/次数上限）、代理（可选：无代理/系统代理/自定义代理）、TLS 校验开关与自定义 CA。
3. 响应预览区展示：HTTP 状态码与文本、响应头、响应时间、响应体大小、响应体（支持 JSON 树形查看、按 key 展开、复制值、原始文本/格式化工 JSON 切换、字符串/数字/布尔/数组/null 高亮；可折叠超长 JSON）。
4. 支持保存最近的响应/历史记录（P1 做历史列表，P0 至少展示当前）。
5. 发送失败时展示清晰错误信息（连接失败/DNS/TLS 错误、超时等），与业务 4xx/5xx 区分。
6. （P1）Cookie 管理（Cookie jar）、会话保持；响应导出/复制为 curl 命令。

### 4.6 断言与分组/项目运行（P1）

1. 断言类型：状态码范围、JSONPath 取值比较、响应头取值比较、耗时上限。
2. 一键运行项目/分组下全部接口，生成通过/失败汇总报告（可导出）。
3. 失败接口支持一键跳转定位。

### 4.7 导入 / 导出（P0 为 OpenAPI，P1 含 Postman）

1. **导入 OpenAPI 3.0 / 3.1**（JSON / YAML 均可）：
   - 按 `openapi.paths` 生成项目（或分组）与接口：每个 `path` 的每对 `(method, operation)` 生成一个接口；按 `tags` 自动建分组。
   - 还原请求头（`parameters.in=header`）、查询参数、请求体示例（`requestBody.content.application/json.example`，无示例时按 `schema` 生成占位）。
   - 还原鉴权（`components.securitySchemes` → Bearer/Basic/API Key）。
   - 导入目标：可选择导入为新项目或合并进当前项目。
   - 导入报告：列出成功/跳过/告警的数量与原因。
2. **导出 OpenAPI**（P0 支持 3.0，P1 支持 3.1 与 YAML 选项）：
   - 以项目为单位导出；接口映射到 `paths[path].OP(operationId, summary, parameters, requestBody, responses(placeholder))`。
   - 从接口的目标方式（可变部分）反向生成 `{{var}}` → OpenAPI 描述或保留原样并记录在导出报告。
3. **导入 Postman Collection v2**（JSON，P1）：
   - 展开 Postman 的 `item` 树 → 项目/分组/接口；还原 body（raw、urlencoded、form-data）、auth、变量（`collection.variable` → 项目全局变量，environment → 环境）。

### 4.8 离线与发布（P0）

1. 启动、使用全程不发任何网络请求，无遥测、无崩溃上报、无自动更新、无需登录。
2. 桌面端发布为离线安装包；Windows 为主目标平台。
3. Windows 依赖 WebView2 Runtime：优先使用系统已安装版本；检测缺失时引导用户安装**离线版** runtime，或随安装包捆绑分发。
4. 支持目标内网的常见 TLS 场景：自定义 CA 证书导入、一键关闭证书校验（带明确风险提示）。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 离线 | 无外网依赖，所有功能本地可用；打包体积尽量小 |
| 数据安全 | 文件原子写；序列化版本校验；异常时不丢数据、不产生损坏文件 |
| 性能 | 启动 < 2s；含 1000 接口的项目流畅展开/搜索；发送请求不阻塞 UI |
| 兼容 | Windows 10/11；后续 macOS / Linux；日志统一写入本地 `logs/` |
| 可移植 | 数据根目录可整体复制/归档/进 git；无隐藏数据库 |
| 可维护 | 数据结构带版本号字段，升级时提供迁移钩子 |
| 安全 | 请求中的敏感字段（如 token）本地明文保存但**绝不写入日志/导出报告**；UI 明示风险 |

## 6. 文件存储格式草案

```
<数据根目录>/
├── workspace.json            # 版本、标签栏状态（打开的项目、当前激活标签）、代理设置
└── api-mgmt/                 # 「接口管理」模块（后续新增模块并列新目录）
    ├── <团队英文键>/           # 团队 = 目录
    │   ├── team.json         # 团队元数据：版本、name(显示名)、描述、创建时间
    │   └── <项目英文键>/       # 项目 = 目录
    │       ├── project.json  # 项目元数据：版本、name、默认环境、全局变量、全局参数
    │       ├── environments/ # 环境（以项目为单位）
    │       │   ├── prod.json         # 正式环境
    │       │   ├── test.json         # 测试环境
    │       │   └── dev.json          # 开发环境
    │       └── api/          # 接口树
    │           ├── <分组英文键>/      # 分组 = 目录（可多级）
    │           │   ├── group.json    # 分组元数据：版本、name(显示名)
    │           │   └── <接口英文键>.json
    │           └── <接口英文键>.json  # 项目可直接放接口
```

> 目录名/文件名统一为**英文**（小写 `[a-z]`、数字 `[0-9]`、连字符 `-`），无空格与其它特殊字符；中文显示名存元数据 `name` 字段。`*.json` 数据文件均为 **JSONC**：读取时容忍 `//`、`/* */` 注释与尾逗号；程序写入时生成标准 JSON。

`workspace.json` 结构（草案）：

```json
{
  "version": 1,
  "openTabs": [
    { "teamId": "team-1", "projectId": "proj-1" }
  ],
  "activeTabId": "proj-1",
  "proxy": { "enabled": false, "type": "system" }
}
```

`project.json` 结构（草案）：

```json
{
  "version": 1,
  "id": "proj-1",
  "name": "示例项目",
  "activeEnvironmentId": "env-prod",
  "globalVariables": [
    { "key": "token", "value": "{{token}}", "enabled": true }
  ],
  "globalParams": {
    "headers": [],
    "cookies": [],
    "query": [],
    "body": { "mode": "none", "content": "" }
  }
}
```

环境文件 `环境英文键.json` 结构（草案）：

```json
{
  "version": 1,
  "id": "env-prod",
  "name": "正式环境",
  "host": "https://api.example.com",
  "builtin": true,
  "variables": [
    { "key": "user", "value": "admin", "enabled": true }
  ]
}
```

分组元数据 `group.json` 结构（草案）：

```json
{
  "version": 1,
  "name": "订单服务"
}
```

接口文件 `接口英文键.json` 结构（草案）：

```json
{
  "version": 1,
  "id": "8f1c…",
  "name": "登录",
  "method": "POST",
  "url": "{{host}}/api/login",
  "headers": [{ "key": "Content-Type", "value": "application/json", "enabled": true }],
  "query": [],
  "body": { "mode": "json", "content": "{\n  \"user\": \"{{user}}\"\n}" },
  "auth": { "type": "bearer", "token": "{{token}}" },
  "assertions": [{ "type": "status-code", "op": "eq", "expected": 200 }],
  "variables": [],
  "description": "# 登录接口\n\n支持 Markdown 的接口说明。"
}
```

## 7. 验收与里程碑

### M0 工程骨架
- `cargo create-tauri-app`，前端 React + Vite + TS；前后端 `invoke` 打通；数据根目录选择入口可打开目录并渲染团队/项目树。

### M1 团队/项目/接口存储 CRUD
- 团队/项目/分组/接口的新建、读取、编辑、删除、重命名、移动；JSONC 宽容解析 + 标准 JSON 写入；原子写；`notify` 外部刷新；中文/特殊字符路径验证。

### M2 接口测试
- 发送请求（全部 body 模式）、变量替换（接口级/项目全局/环境）、全局参数注入、TLS 选项、超时/重定向/代理、响应预览（JSON 树/耗时/大小）、错误分级展示。

### M3 互操作与发布
- OpenAPI 3.0/3.1 导入导出（含 YAML）、导入报告；Windows 离线安装包 + WebView2 引导；UI 中文化。

### M4+ 增强
- 断言与项目/分组一键运行、JSONPath 提取变量、Postman 导入、Cookie jar、OAuth 2.0、历史记录；远期：WebSocket/SSE、rquickjs 脚本沙箱、代码片段生成（curl/Python/Go）。

## 8. 风险与开放问题

1. **文件存储的并发写**：同一数据根目录被多个实例打开时的写冲突策略（锁文件 or 时间戳冲突提示）。
2. **OpenAPI 映射损耗**：请求体示例缺失时按 `schema` 生成占位属于启发式行为，需在导入报告暴露。
3. **WebView2 离线分发**：捆绑超过 100MB 时是否可接受；还是仅提供"检测 + 离线引导安装"。
4. **变量值中敏感信息**：明文持久化在本地文件是可接受的，但要防止意外进入日志与导出。
5. **超长 JSON / 大响应**：响应预览的虚拟化渲染策略（P1）。
6. **JSONC 注释保留**：程序读取宽容、写入生成标准 JSON 会丢失手工注释，是否需要在写入时保留注释（为部分文件引入注释保留的序列化策略）。
7. **团队划分粒度**：离线单机场景下"团队"仅作为项目分组导航，不涉及权限；是否为后续多用户协作预留团队权限字段。

### 待评审问题
- 接口文件命名是否使用"文件名 = 接口名"并用文件重命名语义，还是接口名独立存在（当前采用：独立 `name` 字段，文件名仅作键，重命名不动磁盘时只改字段）。
